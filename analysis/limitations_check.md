# README 한계 점검 결과 (모형 의존성 / 빈도 불일치 / 이상구간 결합)

기존 결과 파일은 수정하지 않았다. 새로 추가한 스크립트와 결과만 아래에 있다.

## 1. 모형 의존성
`analysis/shap_ml/compare_models.py` -> `analysis/shap_ml/results_model_compare/model_comparison.csv`

같은 이상구간 자료, 같은 시간순 80/20 분할에서 RF, XGBoost, Ridge를 비교했다.

| 데이터 | 테스트 R2 | M2_KOR SHAP 순위 (RF/XGB/Ridge) |
| --- | --- | --- |
| 수준값 | -0.90 / -1.05 / -2.00 | 2 / 1 / 3 |
| 21일 변화율 | -0.17 / -0.14 / -0.03 | 2 / 2 / 2 |

- 수준값 테스트 구간의 M2_KOR, M2_USA는 100%가 학습 범위 밖이다. RF는 외삽을 못 해서 R2가 음수다.
  README의 RF importance 0.963(M2_KOR)은 M2가 시간 대리변수여서 나온 값일 가능성이 크다.
- 모델을 바꾸면 M2_KOR 순위가 1~3위로 바뀐다. 모형 의존성이 실제로 크다.
- 변화율로 바꾸면 세 모델 모두 policy_spread 1위, M2_KOR 2위지만 R2가 0 이하라 설명력이 없다.
- 21일 변화율은 블록 안에서만 계산해 표본이 542행으로 줄었다 (아래 3번 참고).

## 2. 빈도 불일치 (점검만, 파이프라인은 미수정)
- `create_daily_integrated_dataset.py`가 월별 M2를 선형보간해 일별로 만든다. M2_KOR는 99.3%의 날에 값이 바뀐다.
- 보간은 다음 달 값을 사용하므로 예측 문맥(Granger, LSTM)에서는 미래 정보가 섞인다.
- 월별 M2의 일별 변화율은 한 달 안에서 거의 상수여서 "일별 선행성"으로 해석하면 안 된다.

## 3. 이상구간 결합
`analysis/m2_components/granger_block_safe.py` -> `analysis/m2_components/granger_block_safe.csv`

- 668개 블록 중 중앙값 길이는 1일, 평균 5.4일, 30일 이상은 20개뿐이다 (설정 `min_contiguous_days`는 30).
- 기존 Granger는 변화율만 블록 안에서 계산하고, lag는 이어붙인 행에서 만들어 다른 블록 값이 섞였다.
- 같은 코드로 기존 방식을 재현하면 README와 일치한다 (lag 2, F=25.74).

| 방향 | Lag | 기존(블록 경계 통과) F | 블록 안만 사용 F | p-value |
| --- | ---: | ---: | ---: | ---: |
| M2 -> FX | 1 | 12.43 | 4.34 | 0.037 |
| M2 -> FX | 2 | 25.74 | 2.18 | 0.113 |
| M2 -> FX | 3 | 19.73 | 1.42 | 0.234 |
| FX -> M2 | 1~3 | - | 0.00~1.00 | 0.37~0.98 |

블록 안에서만 lag를 만들면 M2 -> FX 선행성은 lag 2, 3에서 유의하지 않다. README의 핵심 결론이 이 처리에 의존한다.

## 4. 이상구간 정의 방향 오류와 재실행
`analysis/anomaly/rerun_redefined.py` -> `analysis/anomaly/results_redefined/`

- 기존 정의는 30일 이동상관 `<= -0.2`인 날이다. 스프레드가 `한국 - 미국`이라 전통적 관계는 음(-)이므로,
  이 조건은 디커플링이 아니라 전통적 관계가 맞는 날을 뽑는다.
- 연구 동기가 된 2024-11~2025-12에서 `<= -0.2`는 15%, `|상관| < 0.2`는 53%, `>= +0.2`는 33%다.
  기존 이상구간 3,588일 중 이 기간은 3.5%뿐이다.
- 커밋된 `period_definition.json`(3,588일, 668블록)은 현재 코드와 데이터로 재현되지 않는다(3,350일, 495블록).

세 가지 재정의(A: `> -0.2`, B: `|상관| < 0.2`, C: `>= +0.2`)로 블록 안 lag Granger를 다시 돌렸다.

| 정의 | 블록 최소 길이 | M2->FX p-value (lag 1 / 2 / 3) |
| --- | ---: | --- |
| A | 1 | 0.71 / 0.96 / 0.93 |
| A | 30 | 0.74 / 0.92 / 0.88 |
| B | 1 | 0.95 / 0.92 / 0.88 |
| B | 30 | 0.30 / 0.25 / 0.37 |
| C | 1 | 0.83 / 0.95 / 0.96 |
| C | 30 | 0.82 / 0.87 / 0.90 |

- 모든 정의와 lag에서 M2->FX는 유의하지 않다. 정의를 바꿔도 선행성 근거가 나오지 않았다.
- SHAP 모형 비교는 대부분 테스트 R2가 음수이고 M2_KOR 순위가 모델마다 다르다. 정의 B의 RF 수준값 한 건(R2 0.39)만 양수이고 XGBoost와 Ridge는 음수여서 견고하지 않다.
- 한계: 정의 B의 30일 이상 블록은 18개뿐이라 검정력이 낮다. M2는 월별 보간값이라 일별 Granger 자체가 약한 검정이다.
- 아직 새 정의로 다시 돌리지 않은 것: 임계점 회귀(MMF/CMA), LSTM/Hybrid, 환율 영향 확장.

## 5. 임계점 회귀 재실행
`analysis/daily_threshold_MMF/rerun_redefined.py` -> `analysis/daily_threshold_MMF/results_redefined/`

- 기존 `analyze_daily_threshold.py`는 이상구간 레짐 정의를 쓰지 않는다. 전체 표본에서 임계값을 찾고 고정기간(2024-11 ~ 2025-12)의 초과 빈도만 센다.
- 입력 `M2_proxy`(CMA+MMF)는 현재 `merged_daily_liquid.csv`에 없고, 원본 환율 파일(`환율_일별.csv`)도 저장소에 없다. CMA와 MMF로 프록시를 다시 만들면 2015-12-02 ~ 2026-03-16(2,531일)뿐이다.
- 임계값 6.57조 원(기존 5.1조 원), 부트스트랩 sup-F 검정 F=3.65, p=0.199(B=300). 임계 효과가 유의하지 않다.
- 임계값 초과 빈도(이상구간 안 대 밖): 고정기간 3.16% 대 3.07%, 초기 정의 3.00% 대 3.12%, A 3.31% 대 2.48%, B 3.43% 대 2.76%, C 3.07% 대 3.09%. "약 2배"는 재현되지 않았고 Fisher 검정도 모두 유의하지 않다(p=0.30~1.00).
- 주의: `data/process_scripts/process_daily_data.py`는 원본 환율 파일이 없으면 `USD_KRW_processed.csv`를 빈 파일로 덮어쓴다. 저장소에서 직접 실행하지 말 것.

## 6. MMF LSTM 재실행
`analysis/LSTM/rerun_redefined.py` -> `analysis/LSTM/results_redefined/` (요약: `lstm_summary_all.csv`)

기존 `lstm_mmf/train_eval_extended.py`의 학습·평가를 그대로 쓰고 이상구간 정의(`period_definition.json`)만 바꿔 시드 42로 돌렸다.

| 정의 | 평가 블록 | RMSE 금리차 단독 | RMSE 유동성 추가 | 개선폭 |
| --- | ---: | ---: | ---: | ---: |
| 초기 정의 (README 기존 값) | 546 | 21.16 | 16.62 | 4.54 |
| 초기 정의 (재실행) | 546 | 15.64 | 15.37 | 0.27 |
| A: 상관 > -0.2 | 424 | 16.50 | 22.72 | -6.22 |
| B: \|상관\| < 0.2 | 398 | 14.37 | 14.14 | 0.24 |
| C: 상관 >= +0.2 | 402 | 13.60 | 15.94 | -2.34 |

- 같은 정의로 재실행하면 금리차 단독 RMSE가 21.16에서 15.64로 달라진다. README의 개선폭 4.54는 재현되지 않았다.
- 정의를 바꾸면 개선폭의 부호가 바뀐다(B +0.24, A -6.22, C -2.34). 일관된 개선이 없다.
- 시드가 하나라 우연과 구분할 수 없다. 시드 반복, 평균·표준편차, Diebold-Mariano 검정이 필요하다.
- 한 번에 30~100분이 걸린다(CPU 경합 시 더 길다). 수시입출식 LSTM과 Hybrid는 재실행하지 않았다.
